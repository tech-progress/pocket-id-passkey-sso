# Pocket ID security disposition — October 6, 2026

This is a finite selected-version/default-boundary evaluation, not a claim of zero vulnerabilities or an independently audited reverse proxy.

Pocket ID `v2.17.0` is deliberately selected by immutable image digest. `v2.18.0` was released October 4, 2026 and is newer; this recipe does not describe 2.17.0 as latest. The two newest published [Pocket ID advisories](https://github.com/pocket-id/pocket-id/security/advisories) reviewed for this qualification were fixed in 2.15.0; selected tagged source includes their PAR parsing and device-confirmation fixes. Maintenance and later dependency fixes remain operator responsibilities.

Selected upstream locks include devalue 5.9.1/5.9.2 within published advisory ranges. The tagged frontend uses static output, disables SSR, and calls JSON APIs through Axios. The reviewed default does not establish a request-controlled invocation of the affected serialization functions. This is a scoped exposure observation, not an assertion that the packages are patched, absent from every artifact or globally harmless. Consult [devalue advisories](https://github.com/Rich-Harris/devalue/security/advisories) before introducing server-side rendering or new serialization paths.

The custom Python gateway buffers bodies/responses up to 16 MiB, limits concurrent handling to 64 slots, applies bounded socket/upstream waits, strips untrusted forwarding and operator-cookie headers, requires canonical origin/host, and fails closed on missing/corrupt activation, unavailable SQLite or mismatched issuer/key/owner state. It does not support streaming/WebSockets or establish resilience against sustained hostile traffic. Railway edge/rate-limit behavior and upstream audit logging have separate operational limitations. The public health route is readiness, not identity or bootstrap authorization.

The supported default remains one trusted operator and a single-node small-team issuer, initially locked. Native administrator authorization is separate from operator access. Two stored passkey records do not prove independent physical custody; browser-test virtual authenticators demonstrate protocol execution only. Protect the stable encryption key, operator token, cold backups and recovery links. Neither a healthy deployment nor a successful fixture is proof of hostile-tenant isolation, HA, hardware recovery custody or production capacity.

The finite review found no concrete demonstrated default request-reachable unpatched advisory requiring a source-only publication hold in the reviewed evidence. Complete native/embedded/transitive vulnerability and supply-chain assessment remains unclaimed. Actual final-source Railway TLS/enrollment/authorization/OIDC/recovery/soak and accepted cleanup are independent [publication gates](PUBLISHING.md).
